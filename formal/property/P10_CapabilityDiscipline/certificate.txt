What "unbounded" means here
---------------------------
The conjunction of checks [2] (base), [3] (step) and [4] (implication) is a
standard inductive-invariant argument, so INV_P10 holds in EVERY reachable state
of the Sec. 5 release machine, for an arbitrary number of Sign / IssueChallenge /
ReleaseByOwnership / ReleaseByGrant / Revoke / Tick transitions. The capability
world (hosts, subjects, pubkeys, records) is a finite parameter fixed by
Access.AcConstInit; the inductive argument is per-request local and uniform in
that world size -- confirmed by re-running [2]/[3]/[4] at a larger world (3
subjects, 3 pubkeys, 4 records, MaxTime = 4; see notes.md). Data-domain
finiteness per state is intrinsic to SMT-based model checking and is recorded as
a modelling parameter, not a hidden bound on the number of transitions.

Spend escalation -- STRUCTURAL, not dynamically exercised
---------------------------------------------------------
The fourth Pass-3 attack class (escalating a view capability into a spend) is a
BY-CONSTRUCTION property of the release machine and is deliberately NOT a
conjunct of the machine-checked INV_P10. The grounds:
  (1) The release actions' write set is { acConsumed, acReleased }. No action in
      AcNext writes the signing oracle `acAuthorised` except the honest `Sign`
      action; there is no spend-granting action in the Access machine, so a
      release (a read) can never confer signing/spend authority.
  (2) The VIEW/SPEND key separation is a Foundations/Assumptions-level axiom
      (A9: hardened BIP-32 derivation; a view key cannot derive sk0).
  (3) Bearer secrets (zkview/zkavk) carry no ownership/grant capability, so the
      release predicate is FALSE for them (Sec. 5.1 para 2); CanDecrypt over
      already-public ciphertext is independent of `acReleased`.
An earlier revision shipped this as a machine invariant
  \A e \in acReleased : \A pk \in Pubkeys : CanDecrypt({pk},pk) => e.rec \in Records
which is a TAUTOLOGY (CanDecrypt({pk},pk) == pk \in {pk} == TRUE, and
e.rec \in Records holds for every audit entry by AcTypeOK), asserting nothing
about spend authority. It has been removed rather than shipped as a vacuous
claim. This certificate's verified headline is therefore the three dynamic
invariants above; spend escalation is recorded as structural.

Negative control (the chan_bind gate is load-bearing)
-----------------------------------------------------
The release actions let the requester PRESENT a chan_bind for some host `h`
(possibly ForeignHost -- a proof captured by / bound to a different node, the
Sec. 5.1 proof-forwarding / MITM case) and carry that presented binding through
to the audit entry's `host` field. The only thing preventing a ForeignHost-bound
proof from releasing is the admit predicate's ChanBindMatches(presented,
ServingHost) plus the challenge-side equality ch.chanBind = presented.

Deleting BOTH ChanBindMatches conjuncts (from OwnershipAdmits and GrantAdmits) in
a throwaway copy of Access.tla (/tmp, not committed) and running
  apalache-mc check --cinit=P10ConstInit --init=AcInit --next=AcNext --inv=INV_P10 --length=4 property.tla
yields "The outcome is: Error" with AcNoReplayAcrossHosts (INV_P10's third
conjunct) VIOLATED at State 3:

  State2: acIssued = { [chanBind |-> 20, expiry |-> 1, nonce |-> 1, subject |-> 1] }
          (IssueChallenge bound to host 20 = ForeignHost)
  State3: acReleased grows with two entries, each host |-> 20 (ForeignHost)
          => AcNoReplayAcrossHosts violated: e.host (20) != ServingHost (10)

i.e. without the gate, a proof presenting a ForeignHost binding releases at a
foreign host -- a genuine cross-host replay (a proof bound to host X accepted at
host Y), exactly the Pass-3 P10 "replay against a different node" win. With the
gate present, all four checks return NoError. (A prior certificate claimed
deleting the chan_bind conjunct returned NoError because the release actions then
hardcoded host |-> ServingHost; that made the negative control and the invariant
vacuous. The release actions now carry the presented binding through, so the
control is a real violation. Trace recorded in notes.md.)
