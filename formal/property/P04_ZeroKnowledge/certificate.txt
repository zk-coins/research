Dynamic vs structural vs axiom (the honest split)
-------------------------------------------------
  DYNAMIC (machine-checked, non-vacuous, negatively controllable):
    INV_P4_flow == ~ obsTainted. A composed machine = the module/Proofs.tla
    per-account proof lineage (which PUBLISHES ProofData) + an adversarial
    observer that scrapes the public projection and pulls provenance-tagged
    items into a leak set, GATED by the Sec. 2.1 clause-9 publication
    discipline (only public-channel items: ocrIdx / owner / nextPk / counter).
    obsTainted flips iff a pulled item is tagged with a WITNESS channel
    (amount / nk / recipient). The committed gate never exposes such an item,
    so the flag stays down in every reachable state -- proven unbounded by the
    inductive triple [2]+[3]+[4]. Genuinely dynamic: the public view and the
    leak set grow as the lineage runs; the negative control (widen the gate
    with a witness-channel item) makes a leak reachable.

  STRUCTURAL (stated, labelled, NOT a dynamic conjunct -- the P10 pattern):
    PublishedCarriesNoWitnessField. The published record TYPES carry no witness
    field by construction: ProofData has exactly {newAsh, ocr, inr, chRoot};
    the delivery-event plaintext has exactly {detectTag, epk, blobId,
    blobLocators, ackNonce} (Transport.MkDeliveryEvent); the on-chain
    BatchInscription's only witness-relevant field is batchNullifiers, a set of

Negative control (the clause-9 gate is load-bearing) -- REAL violation
----------------------------------------------------------------------
In a throwaway copy of property.tla (/tmp, not committed) the committed gate was
WIDENED to expose a witness-channel item (the nullifier key nk):

  CommittedGate(w, pd) == PubItems(w, pd) \union { Item("nk", w.nk) }

  apalache-mc check --cinit=ConstInit --init=Init --next=Next
    --inv=INV_P4_flow --length=4 property.tla
  -> The outcome is: Error -- INV_P4_flow VIOLATED at State 1:
       State0: obsTainted = FALSE, obsLearnt = {}
       State1: obsLearnt = { [chan |-> "nk", val |-> 1] }, obsTainted = TRUE
               => ~obsTainted is FALSE  [witness datum reached the observer]

i.e. with the gate widened to expose nk, the adversarial Observe pulls a
witness-channel item, the leak flag flips, and the flow invariant breaks --
exactly the Pass-3 P4 "leakage through a witness channel" win the clause-9
discipline rules out. With the committed gate (public channels only), all four
verify.sh checks return NoError. The gate is genuinely load-bearing. The
committed property.tla and the module files are unchanged; the /tmp copy and its
_apalache-out were discarded.

The channel-provenance design (vacuity-trap avoidance, recorded for audit)
--------------------------------------------------------------------------
An earlier draft tested the leak with a VALUE-level cross-domain test
(`pulled \cap WitnessOnlyScalars(w) # {}`). It produced a SPURIOUS violation:
in the smoke instance the owner address, the nullifier key nk, and the mint
amount were all the same Int (2), so a pull of the PUBLIC owner item tripped the
witness test by numeric coincidence -- the exact Int-domain trap the M4 ground
truth warns about. The model was rebuilt to tag every exposed/leaked datum by
its PROVENANCE CHANNEL ([chan, val]); the leak test is now `\E it \in pulled :
it.chan \in {"amount","nk","recipient"}`, a structural statement about which
channel carried the datum, immune to value coincidence. This is the load-bearing
content of P4's dynamic half.
