What "unbounded" means here
---------------------------
The transport state machine has a genuinely infinite reachable state space:
Retry increments the per-attempt ack_nonce without bound. This proof removes
the execution-length bound: the conjunction of checks [2] (base), [3] (step)
and [4] (implication) is a standard inductive-invariant argument, so INV_P8
holds in EVERY reachable state, for an arbitrary number of
Publish / Replicate / RecipientSigns / Ack / Retry / Drop transitions.

The proof instance fixes finite parameters via TrConstInit (K = 3,
Holders = {1,2,3}, RecipientOpPk = 10, IvkHolders = KtxHolders = {20,21},
Eve = 99) and a finite nonce universe NonceU = 0..3 for the START state of the
step check (the POST-state invariant places no bound on the nonce, so a Retry
stepping to a successor outside NonceU is still checked). The inductive
argument is uniform in these sizes: every conjunct is a local structural fact
coupled only by equality, and every action preserves it independently of
|Holders| and the nonce range. Confirmed by re-running [2]/[3]/[4] at the
larger instance Holders = {1,2,3,4}, NonceU = 0..6 -- all three NoError (see
notes.md). Data-domain finiteness per state is intrinsic to SMT-based model
checking and is recorded as a modelling parameter, not a hidden bound on the
number of transitions.

The inductive invariant
-----------------------
  IndInv == TrTypeOK /\ INV_P8
where INV_P8 == TrAvailabilityNotSafety /\ TrAckFreshness
                /\ TrSenderRetainsUntilSafe.

  - TrAvailabilityNotSafety is a constant predicate over the holder sets
    (Eve is in neither IvkHolders nor KtxHolders), preserved by every action.
  - TrAckFreshness (trAckOk => the recipient signed THIS attempt's ack tag) is
    the genuinely inductive conjunct: Ack sets trAckOk only via AckAccepts,
    whose nonce-equality binds the accepted ACK to trAttemptNonce; Retry only
    advances the nonce while trAckOk = FALSE (so freshness is vacuous after a
    retry).
  - TrSenderRetainsUntilSafe is preserved because Drop is guarded by
    trAckOk /\ |trReplicas| >= K, and every action is guarded by
    trPhase = "published" -- once dropped, the state is frozen.
  TrTypeOK supplies the finite state-bounding facts (phase domain, replica set
  subset of Holders, A7 oracle holds only the recipient's op key) the SMT step
  needs. No further strengthening was required.

IndInvInit is the assignment-form restatement of IndInv used as the --init
predicate of the step check (Apalache requires each variable ASSIGNED, not
merely constrained). It assigns each variable from its finite type domain and
then asserts IndInv; it is logically equivalent to IndInv.

spec-v1.1 (docs#47 §4.2.1) -- ZBE ANTI-TRUNCATION (zbe.tla)
================================================================================
docs#47 §4.2.1 adds ZBE: the bundle blob is sealed with chunked
ChaCha20-Poly1305, per-chunk AAD "zkCoins/v1/Blob" || u32_be(N) || u32_be(i)
binding total chunk count N and index i. Confidentiality (INV_P8) is UNCHANGED
(diff-confirm): ZBE is a thin chunked framing over the SAME AEAD primitive and
reduces to A10, so who-can-read (CanDecrypt/CanReadBundle) is untouched. The
genuinely NEW guarantee -- previously hand-argued -- is INTEGRITY / ANTI-
TRUNCATION: a truncated, extended, or reordered chunk sequence does not
authenticate, so an accepted plaintext equals exactly the sealed plaintext.

zbe.tla (self-contained) models the A10 AEAD as: a chunk carries its AAD-bound
(n, idx); ChunkAuth(c, obsN, pos) == c.n = obsN /\ c.idx = pos-1 (the tag
verifies IFF the chunk's sealed (N,i) matches the AAD the receiver computes at
its position); Accepts(rx) == Len(rx) >= 1 /\ every chunk authenticates (missing
magic / count / index mismatch aborts -- no partial accept). The adversary may
truncate/extend/reorder/duplicate. Proven UNBOUNDED:
  [Z2] base   Init => IndInv      (IndInv = TypeOK /\ AntiTruncation)
  [Z3] step   IndInv /\ Next => IndInv'   (init via sealed/received = Gen(MaxN))
  [Z4] impl   IndInv => AntiTruncation     (accepted => received = sealed)
[Z1] bounded sanity (length 4) supports; [Z5] is a vacuity probe (NeverAccepted
returns a counterexample => accepted=TRUE IS reachable, so AntiTruncation is
exercised with a TRUE antecedent, not vacuously).

An honest modelling note: the first Accepts had no Len(rx) >= 1 clause, so an
EMPTY received vacuously authenticated and [Z3] failed with a counterexample; the
fix -- reject a zero-chunk delivery -- is faithful to "missing magic MUST abort"
and is a STRENGTHENING, not a weakening.

  apalache-mc check --cinit=ConstInit --init=Init       --next=Next --inv=IndInv         --length=0  zbe.tla  # [Z2] base

  apalache-mc check --cinit=ConstInit --init=Init       --next=Next --inv=AntiTruncation --length=3  zbe_nc.tla  # [Z6] negative control (expect Error)

Negative control (the per-chunk (N,i) AAD binding is load-bearing)
-----------------------------------------------------------------
The committed companion zbe_nc.tla DROPS the (N,i) binding -- ChunkAuth becomes
TRUE regardless of (n,idx). Running:
  apalache-mc check --cinit=ConstInit --init=Init --next=Next --inv=AntiTruncation --length=2 zbe_nc.tla
yields a counterexample (The outcome is: Error, exit 12) at State 1:
  sealed   = << chunk(n=1, idx=0, payload=2) >>                    (one chunk)
  received = << chunk(n=1, idx=0, payload=2),
                chunk(n=1, idx=0, payload=2) >>   accepted = TRUE  (DUPLICATED)
          => received != sealed yet accepted => AntiTruncation violated.
So with the binding dropped an extended/duplicated (and, symmetrically,
truncated/reordered) sequence authenticates while differing from the sealed one
-- the definitive proof the (N,i) AAD binding is load-bearing. The committed
zbe.tla is unchanged; the negative-control _apalache-out was discarded.
